# 任务生命周期

一次提交从点击按钮到出片，中间发生了什么，以及每一步谁负责。
理解这条链路能省掉大量「为什么我的字段没发出去」「为什么状态一直是排队中」的排查时间。

---

## 全链路

```
用户点「开始生成」
  │
  │ ── 前端即时校验（plugin-schema.ts）
  │      不通过就禁用按钮 + 提示，不发请求
  ▼
① 顺序上传参考素材                        POST /api/nova/plugin-media
  │    每个文件一个请求，逐个上传（不并发——一次 9 个会打满限流）
  │    图片先在浏览器里重编码成 WebP
  │    返回本机公网 URL
  ▼
② 创建任务                                POST /api/nova/plugin-tasks
  │    后端权威校验（input.js）→ 落库 status=排队中 → 进队列
  │    素材绑定到该任务（此后随任务一起清理）
  │    apiKey 存进内存 Map，不入库
  ▼
③ 等并发名额（drainQueue）
  │    插件任务每个占 1 个名额，名额从「开始跑」持有到「轮询出终态」
  ▼
④ 创建上游任务                             provider.submit
  │    status=processing，记下 upstreamTaskId
  │    失败 → 标失败，按视频保留期回收
  ▼
⑤ 轮询到终态                               provider.poll
  │    每 intervalMs 一次；单次失败不判死，等下一轮
  │    每轮更新进度与上游状态（不入库，进程内存）
  │    超过 maxTotalMs → 判失败并释放名额
  ▼
⑥ 完成                                    result_json = { assets: [...] }
  │
  ▼
⑦ 前端轮询拿到 completed                   GET /api/nova/plugin-tasks/:id
       写入本地历史 → 发 ack（视频不缩短保留期）
```

---

## 两种「排队中」

界面上会区分，因为原因完全不同：

| 显示 | 含义 | 处理 |
| --- | --- | --- |
| 本机排队中 | 本服务器并发名额满了，还没轮到发上游 | 等，或让管理员调 `NOVA_TASK_CONCURRENCY` |
| 上游排队中 | 已经发给上游了，上游那边在排队 | 只能等 |

对应到数据上：`status` 是本机队列状态，`upstreamStatus` 是归一化后的上游状态。
`status=processing` 且 `upstreamStatus=queued` 就是「已提交，上游在排」。

---

## 进度是怎么算的

总进度分两段，上传占 40%，生成占 60%（生成通常远比上传久）：

- **上传段**按字节加权，不是按文件数——一个 30MB 的视频和一张 200KB 的图不该各占一半
- **生成段**读 `provider.poll.progress` 指定的字段

**两段都是真数，没有任何时间估算。** 上游那一轮没给 `progress` 时，界面切成不定量
动画 + 已用时间，而不是编一个数字。这是刻意的取舍：一个缓慢爬升的假进度条
在任务其实已经失败时会让用户白等十分钟。

「生成用时」从 `generationStartedAt`（上游任务创建成功那一刻）算起，
而不是从提交算起——否则上传耗时会被算进生成里。

## 素材的生命周期

上游的视频接口普遍只接受 URL，不接受 base64 或 multipart，所以素材必须先落到本机、
再把公网地址交给上游去拉。

```
选中文件（内存）
  → 点提交后才上传（选中即上传会让没提交的文件白占磁盘）
  → 落盘 backend/data/plugin-media/<uuid>.<ext>
  → 绑定到任务（bindToTask）
  → 任务过期/被删 → 素材一起删
  → 没绑定过的孤儿素材按 TTL 清理（缺省 24 小时）
```

几个要点：

- 嵌入模式上游使用 24 小时 HMAC 签名链接，用户预览走鉴权 preview；原始素材匿名读取返回 404
- 同一用户重复选同一个文件会命中去重（嵌入模式哈希键含用户 ID，独立模式含 IP），但**已绑定任务的素材不参与复用**：
  否则删任务 A 会连带删掉任务 B 还在用的文件
- schema 的 allowRemoteUrl=true 时允许 HTTPS 外链，与上传 URL 混合
- 部署在内网时上游拉不到素材，需要配 `NOVA_PUBLIC_BASE_URL`

---

## 失败时的清理

下载失败会清理不完整的结果文件；素材随任务保留，过期或删除时一起回收。
上游已生成但下载失败时错误附带上游任务 ID，并明确已计费。

---

## 服务器重启

所有未终态任务一律标失败（「服务器重启，任务已中断」）。

不做恢复是有意的：apiKey 只在内存里，重启后无从继续轮询；而进度是过程量，
本来也没入库。让用户看到一条明确的失败比看到一条永远转圈的任务好。

---

## ack 是干什么的

视频任务 ack 不缩短保留期；嵌入图片同样保持 7 天保留期。
视频从终态起默认保留 3 天，处理中不设提前过期时间。后端独立轮询，GET 只读数据库。
